# Wrist-roll zero verification before re-pinning — 2026-11-27

Brian: "verify and re-pin". This is the verification that preceded the re-pin, and
what it means for the 5.3° worry I raised.

**Outcome: the model frame largely survived the accepted zero. The re-pin is
justified; a measured roll-zero residual of ~0.7–2.1° remains and is absorbed by
the per-session board pose. `model_offset_deg` was NOT changed — the estimate was
not stable enough across two runs to justify writing a correction.**

## Method

Five poses differing **only** in `wrist_roll` (−10, −5, 0, +5, +10 at a posture
with 9–10 markers in view), arm homed before and after, gripper held at its
measured value and not actuated. Each view: planar PnP gives the observed
camera-from-board with the calibrated lens; FK at the measured joints through the
pinned mount gives the predicted one. Then one shared roll-zero correction `delta`
is fitted together with a free board pose, so a stale board cannot masquerade as a
joint-zero error.

Run twice, independently.

## Result

```
run 1   delta = -2.08 deg   fit rms 2.10 px
run 2   delta = -0.74 deg   fit rms 2.12 px
per-view PnP rms  1.28 - 1.70 px (both runs)
```

So the correction is small and not stable: two runs of the same configuration
disagree by 1.34°, which is the size of the effect itself. The 5.3° I predicted
from the servo homing count change (629 → 509) is **not** present — that mapping
was my inference, not a measurement, and the measurement does not support it.

Sketch of the conditioning problem: with only one joint moving, a roll-zero error
and a mount rotation about that same wrist-roll axis are nearly degenerate. The
board pose is free, so the fit has somewhere to put the rest. Separating them
properly needs poses that vary more than one joint, which this run deliberately
did not do.

## Decision

- **Re-pin the live state as it is.** The pin's job is to catch future drift from
  the rig as measured today, not to certify optical accuracy. Pinning the current
  file means the next unexpected change is visible again.
- **Do not synthesise `model_offset_deg`.** Writing +2.08° from run 1 and −0.74°
  from run 2 would be picking a number by hand from a noisy estimate — exactly
  the kind of quiet calibration edit that later reads as authoritative.
- **Record the residual.** A ~1–2° roll-zero uncertainty exists and is currently
  absorbed by the per-session board registration. If it matters for a gate, the
  way to settle it is a mixed-joint capture (roll plus pan/lift), not another
  roll-only series.
