## 2. Mask — the exact mismatch, and what I tried

The mask is **entirely the CAD tool**: per-link decomposition gives 0.0 % for
base/shoulder/upper_arm/lower_arm/wrist and **47.8 %** for the five tool meshes
(48.2 % union). It is identical on every frame because the tool is rigidly fixed
to the camera.

Where the geometry actually sits, in the camera frame at a cal posture: tool
centroid **x +50 mm, depth 55 mm** — 42° off axis, outside the 28.6° corner
half-angle — but the jaws sweep through the axis, so the silhouette covers half
the frame. A depth sweep shows where the coverage comes from:

| near plane | coverage |
|---|---|
| 1 mm | 48.2 % |
| 20 mm | 48.2 % |
| 60 mm | 44.2 % |
| 80 mm | 17.9 % |
| 100 mm | 10.5 % |
| **140 mm** | **0.0 %** |

Attempts, all measured and all rejected as fixes:

1. **Physical 20 mm near plane** (`near_plane_m`) — no change (48.2 %):
   not a clipping sliver.
2. **Cull triangles straddling the lens plane** — no change (48.2 %):
   the geometry is genuinely in front.
3. **Twelve rigid re-mounts** (0/90/180/270° about each tool axis) — coverage
   10.1 % … 100 %; the best (10.1 %) still covers tags that decode.

Conclusion: the model puts the tool **60–140 mm in front of the lens**; the real
frames contain no tool at any depth. To be invisible the tool has to be
≥140 mm behind where the model mounts it (profile `mount_position` z is
−62.6 mm). That is not a rotation I can justify from geometry alone, and
the camera itself is **not** at fault: its board reprojection is
**1.32 px median** on the same frames.

**Why the 4c gate did not catch this:** it compares *ChArUco corner
reprojections*. A misplaced tool adds no corners, so the gate is blind to it by
construction. Worth fixing in the gate itself.

I stopped rather than shift the tool by a number I cannot measure — that is the
"disable it in effect" the brief forbids.
