## 1. Jaw A/B — measured, and negative

Four frames per pose after a 2 s settle, speed 0.3, same targets. **Gripper
commanded vs measured:**

| commanded | measured |
|---|---|
| 0 (what my 5m script sent) | **0.9** |
| **45** | **44.17** |
| **78.5** | 78.2 (same 1:1 tracking) |
| plan jaw 0.0 rad → app command **50** | ~49 |

The jaw maps and tracks 1:1 — there is no servo-mapping bug. The plan's jaw is
`0.0 rad`, which `_sim_jaw_to_command` maps to **50**, so the 5l scan ran at
~50, not at 0.9; the 0.9 readings came from my own 5m script, which commanded
`joints[5] * 100 = 0`.

Sharpness (mean of 4 frames) vs jaw:

| pose | jaw 0 (5m) | jaw 45 | jaw 78.5 |

| marker26 | 66.1 | 66.5 | 64.3 |
| marker24 | 39.4 | 39.0 | 39.2 |

| marker14 | 180.7 | 179.2 | 179.9 |

Decoded tags are identical across jaw states (0/0/0; marker23 one tag; marker14
three). **The jaws are not occluding or softening the view.** Montage:
`reports/block5n_jaw_ab.png`.

The frames are also stable across the four shots (spread < 5), so it is **not
settle timing or motion blur**.

## 2. Incidence gate — added, and a no-op for this plan

`tools/plan_marker_scan.py` now rejects a candidate whose view axis is more than
`--max-incidence-deg` (default 40°) off the board normal, in addition to the
3-tag / 12 px / bridge-limit gates.

Measured incidence of the current 13-pose plan (the plan stores radians; the
first pass of this check double-converted and gave a bogus 60°):

```
n 13   min 0.0°   median 0.0°   max 0.2°   camera height 593.7 mm (= board + 160)
```

So every pose is nadir and the gate correctly admits them all. Regeneration at
160 mm reproduces the same 13 poses (3–5 tags each, min edge 104 px, worst joint
margin +7.05°). Validation is unchanged from 5g: **7/7**, ≤0.10 mm / 0.016°.

## 3. The anomaly this leaves

The model says these poses are **0° incidence at 160 mm**. The bench frames at
the same joints are: one nadir and sharp (marker14, sharpness 180) and four
oblique-looking and soft (39–66), with the board edge and the table in frame.

That is not jaws, not settle, not incidence *as modelled*. Either the real
camera's aim at these postures differs from the model by tens of degrees, or the
arm is not where the encoders say. It is the same class of question as the 5c
tool mount, and it needs the same kind of evidence: one pose, FK-predicted view
vs real frame, side by side.
