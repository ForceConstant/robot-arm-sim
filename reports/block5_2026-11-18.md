## The blocker — `/scan` refuses before touching the arm

```fish
curl -s -X POST http://127.0.0.1:8080/scan -d '{}'
→ {"started":true}
```

Two seconds later, `last_scan:null` and:

```
error: pose 'marker71' is outside wrist_roll limits (-87.2 vs -81.8..91.0);
       plan units probably are not degrees
```

This is `ScanController.run()`'s limit precheck, which runs **before the first
pose visit**. Nothing was commanded: `commands_applied` stayed **0**.

The refusal is not a units bug — `plan_in_degrees()` is applied at load. Every
one of the 11 ChArUco plan poses asks for the same `wrist_roll`:

(degrees; `wrist_roll` is a constant pose parameter, so bounding it makes the
whole plan usable or not.)

**Cause.** `marker_scan_plan_charuco.json` was generated by Block 4b against the
MuJoCo scene with unrestricted joint limits (±180). Block 4's "real limits"
work bounded only the 64-square sweep; the scan plan's joint values were never
checked against the bridge's calibrated servo ranges. The plan's coverage was
validated (7/7 placements, 32 markers/scan) — coverage was never the problem.

**Why this stops the block.** `/scan` is the only path that re-registers
`board.json` x/y/yaw. Without it the board frame stays at
`(−13.74, −3.57, 409.48, 7.14)`, whose z was derived with the *old, 2.66×-wrong
lens*; Block 4c's corrected derivation says `(−9.92, −3.13, 431.35, 5.67)` —
**z is 21.9 mm low** and yaw 1.47° off. Running `/sanity`, the dry runs or the
64-square sweep on that frame would not produce a safe or honest result:

- targets at `z=60` would sit ~38 mm above the real playing surface, not 60 mm;
- the achieved-tip error is measured *in the same (wrong) board frame*, so a
  systematic 22 mm z offset would cancel and the sweep could report a clean
  64/64 while the tip is 22 mm below nominal. That is exactly the silent pass
  the run sheet's "do not fudge" rule exists to prevent;
- `/sanity`'s 6 mm corner budget would be measuring a frame, not the arm.

So the run stopped at step 7, per the abort table, and the arm was returned to
`HOLD`.
